## 2. 扩展点设计

代码在以下位置预留了扩展位，新增功能尽量不破坏现有结构：

| 扩展点 | 位置 | 扩展方式 |
| --- | --- | --- |
| 新增科目 | `src/data/subjects.js` + 数据文件 | 增加 subject 记录与对应知识点/题目/卡；UI 自动适配 |
| 新增题型 | `core/grade.js` 的策略表 | 注册 `type → 判分函数`；视图层增加渲染分支 |
| 新增积分来源 | `core/points.js` 的 `SOURCES` | 增加来源常量与规则；流水自动记录 |
| 新增任务指标 | `core/tasks.js` 的 `metrics` | 注册 `metric → reducer(event, state)` |
| 新增稀有度 | `data/cards.js` + 概率表 | 增加枚举与样式类；保底逻辑需同步 |
| 新增书目 | `data/books.js` | 只加元数据，不改代码 |
| 新增统计图 | `components/charts/` | 复用 SVG 基元（轴、网格、路径） |
| 新增存档字段 | `storage/migrate.js` | 提升 schemaVersion 并写迁移函数 |
| 替换存储 | `storage/archive.js` | 保持 API 不变，换成 IndexedDB 或远端 |

## 3. 引入后端的演进路径（可选）

当前无后端是**产品选择**（隐私、零成本、快），不是技术限制。若未来需要跨设备同步：

```
阶段 1：抽象 storage 接口          （当前已按接口隔离）
阶段 2：增加 remote adapter        （Supabase / 自建 Nest）
阶段 3：冲突合并策略               （按 updatedAt + 字段级合并，学习进度以「累加量」为准）
阶段 4：账号与权限                 （仅本人，不做社交）
```

原则：**离线必须始终可用**；同步是增强，不是前提。任何云端方案都必须支持「本地优先 + 手动导出」，避免把学习数据锁在服务里。

## 5. 技术债与已知限制

| 项 | 现状 | 计划 |
| --- | --- | --- |
| 数据整包加载 | 数据量小（< 100 KB），未按科目拆包 | 题量 > 400 时按科目动态 import |
| 单档存储 | 仅一个本地档案 | v1.2 多档案 |
| PDF 句柄兼容 | Safari/Firefox 走 Blob 降级 | 文档说明；不强行 polyfill |
| 无自动化 UI 测试 | 依赖手动清单 | 可选引入 Playwright（成本较高） |
| 图表手写 | 维护成本高于图表库 | 图形种类 > 6 时再评估 |
| 简体中文单语 | 文案常量化 | 有需求时接入 i18n |

- 学习计划生成（按考试日期倒排，自动分配每日任务）
