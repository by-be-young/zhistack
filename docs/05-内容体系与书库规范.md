# 05 · 内容体系与书库规范

## 1. 内容分层

知栈的内容分四层，层层可追溯：

```
书目层  Book（公开出版信息 + 章节结构 + 印刷页码）
  ↓ 映射
章节层  Chapter（章 / 节，承载页码与知识点归属）
  ↓ 聚合
知识点层 Knowledge（可检索、可挂题、可评价的最小单元）
  ↓ 训练
题目层 Question（每题绑定唯一主考点）
```

内容不追求「覆盖全书」，追求「覆盖高频考点且能挂题」。一个知识点如果没有配套题，就没有诊断价值，只能作为检索条目存在——这类条目在数据中标记 `estMin` 并允许无题，但会降低该章节的「可练度」。

## 2. 书目范围

v1.1 收录七科书目的**公开出版信息与章节结构**，作为页码锚点；数学三本、英语与政治使用自编讲义。示例（数据文件中以实际版本为准）：

| 科目 | 主锚定书 | 备选 | 用途 |
| --- | --- | --- | --- |
| 数据结构 | 《数据结构（C 语言版）》严蔚敏 / 吴伟民，清华大学出版社 | 王道《数据结构考研复习指导》 | 章节结构与印刷页码 |
| 计算机组成原理 | 《计算机组成原理》唐朔飞，高等教育出版社 | 袁春风《计算机组成与设计》 | 同上 |
| 操作系统 | 《计算机操作系统》汤小丹等，西安电子科技大学出版社 | 王道复习指导 | 同上 |
| 计算机网络 | 《计算机网络》谢希仁，电子工业出版社 | 王道复习指导 | 同上 |

### 2.1 内容边界

1. 教材正文、图表、例题、课后题、扫描件都可以直接入库，整本 OCR 成读本也可以（见 2.3）。
2. 书目信息按原书登记：书名、作者、版次、出版社、总页数、章节标题、起始页码。
3. 知识点讲义、题目、解析、资料镜像不要求标注来源、年份或「改编」字样。
4. 用户自备 PDF 既可本地挂载（文件存 `IndexedDB`，不上传），也可走 OCR 入库。
5. 所有内容按「个人复习使用」处理，不再逐条做来源核验与声明。

### 2.2 版本差异处理

同一科目的不同版本页码不同。策略：

- 一本书目绑定一个明确版次（`edition` 字段），页码以此版印刷页为准。
- 知识点可挂多个 `bookRefs`（跨书对齐），跳页时优先使用当前打开的书。
- 提供「页码偏移校准」：用户 PDF 的物理页与印刷页存在固定差值时，设置一次即可全局生效。
- 若用户使用其他版本，偏移校准仍可应急使用；文档与 UI 提示「页码以 X 版为准」。

### 2.3 全文读本（例外通道）

面向「手上有扫描件、想要可搜索可跳转的电子读本」的个人复习场景，书库支持把整本书逐页 OCR 成站内正文，**不挂 PDF**。

- 数据位置：`public/booktext/<book>/`，一「节」一个 gzip JSON（`toc.json` 为目录），按需懒加载；正文不进入打包的主 chunk。
- 书目登记：`src/data/booktext.js`，书目 id 与既有书目区分（如 `book-os-wd2025`，章节 id 前缀 `osw-`），必须带 `text` 字段。
- 生成链路：`scripts/ocr-book.py`（逐页 RapidOCR，按页 JSON 可断点续跑）→ `scripts/build-book-text.py`（按 PDF 书签切节、还原段落、聚合图注）。
- 正文块约定：`h3` 节标题、`h4` 小节标题（书签为准，带锚点）、`h5` 节内编号小标题、`p` 正文、`p.item` 编号条目（（1）（一）①）、`p.li` 列表项、`p.tag`【考纲内容】类标签、`p.tip` 命题追踪/注意、`figure.fig` 图注块（`figcaption` 为图题）、`p.figcap` 无标签的图题、`div.pgmark` 原书页码锚点。
- 页面提示：阅读页显示原书页码，并提示「OCR 录入，个别字符可能有误」。
- 下线方式：删除 `public/booktext/<book>/` 与 `src/data/booktext.js` 中对应条目即可，不影响其他书目。

## 3. 章节结构规范

### 3.1 层级

- 最多两级：**章**（`ch`）与**节**（`ch-x`）。不再细分到「小节」，避免维护成本与页码漂移。
- 章必须有 `page`（章首印刷页）；节必须有 `page`（节首印刷页）。
- `page` 单调递增；同一章内节页码必须大于章页码。
- 章标题使用教材原目录标题（事实性），最多 20 字。

### 3.2 章节与知识点的归属

- 每个知识点只归属一个章节（最具体的节）。
- 章节页显示的题量与掌握度为**子树聚合**（含其下所有节）。
- 若某节无知识点，视为索引缺口，构建期告警；连续两节缺口则该章标记「待补」。

### 3.3 页码可信度

每条 `bookRefs` 可带 `confidence`（`exact` / `approx`）：

| 值 | 含义 | UI 处理 |
| --- | --- | --- |
| `exact` | 已核对纸书，页首即该内容 | 直接显示 `p.132` |
| `approx` | 按目录推算，可能有 1–2 页偏差 | 显示 `p.132±` 并提示可微调 |

## 4. 知识点规范

### 4.1 粒度

一个知识点 = 一个可在 3–15 分钟内讲清、可被 3–10 道题检验的概念簇。

合格：
- 「页式存储的地址转换」（含页表、TLB、多级页表的关系）
- 「TCP 拥塞控制的四个阶段」
- 「补码表示与溢出判断」

不合格（过粗 / 过细）：
- 「操作系统」（过粗）
- 「页表项第 12 位的含义」（过细，应并入上位概念）

判据：如果两条知识点的题经常互相串，说明应合并；如果一条知识点下的题需要完全不同的前置知识，说明应拆分。

### 4.2 标题与编号

- 标题 8–24 字，名词短语，不加书名号与问号。
- 考点编号格式 `<科目前缀>-<章>.<节>-<两位序号>`，例 `OS-3.2-04`。编号一旦分配不复用。
- 同一知识点的编号在所有书目中保持一致（编号是跨书锚）。

### 4.3 摘要写法（结论先行）

`summary` 40–80 字，结构为「是什么 + 关键机制 + 常考角度」：

> 通过页表把虚拟页号映射到物理页框，TLB 缓存近期映射；常考多级页表的地址切分与缺页处理流程。

禁止：以「本章介绍……」开头、复述标题、加入个人感叹。

### 4.4 要点与易错点

- `points` 3–6 条，每条 15–45 字，一条只讲一件事。
- 允许行内标记：`**加粗**` 用于结论，`` `code` `` 用于符号与公式片段，`[[k-xx-xx]]` 用于内链。
- `pitfalls` 0–3 条，写「错在哪 + 正确理解」，例：「把 TLB 命中等同于 Cache 命中——两者层级与失效时机不同。」
- 不使用「很重要」「必考」等空话；如果要强调，用具体频次或题型说明。

### 4.5 内链

- `related` 用于横向关联（同章、前置、易混）。
- 正文中的 `[[k-id]]` 渲染为可点内链，构建期校验目标存在。
- 每个知识点至少有 1 条 `related`（构建期校验，可指向同章「上位概念」）。

## 5. 页码映射流程

```
1. 取一本实体书（或可信电子版），翻到目标概念首次出现处
2. 记录印刷页码（页脚数字），不是 PDF 物理页
3. 写入 bookRefs：{ bookId, chapterId, page, confidence:'exact' }
4. 若只按目录推算，标 confidence:'approx'
5. 抽查：随机取 10% 条目复核，偏差 > 2 页则整章重新核对
```

维护节奏：每版教材更新后，先核对目录结构是否变化，再批量复核页码；结构变化超过 30% 则新建 `bookId`，旧书保留只读。

## 6. 内容生产流程

| 阶段 | 产出 | 责任 | 校验 |
| --- | --- | --- | --- |
| 选题 | 高频考点清单（按章节权重） | 内容维护者 | 与题库覆盖率对照 |
| 撰写 | 知识点 JSON（摘要 + 要点 + 易错 + 书页） | 内容维护者 | 字段完整、字数区间 |
| 配题 | 每个知识点 2–8 题 | 内容维护者 | 见 06 命题规范 |
| 交叉校验 | 第二人复核概念正确性与页码 | 复核者 | 抽查清单 |
| 上线 | 合并 → `validate-data` → 构建 | 维护者 | 构建通过 + 抽样点击 |

个人项目可由同一人分时扮演「撰写 / 复核」，但复核必须在撰写完成 24 小时后进行，减少惯性错误。

## 7. 内容质量指标

| 指标 | 目标 | 计算 |
| --- | --- | --- |
| 知识点覆盖率 | 七科高频考点 ≥ 80% | 已收录 / 高频清单 |
| 可练度 | 有 ≥ 2 题的知识点占比 ≥ 90% | 有题知识点 / 总知识点 |
| 书页可用率 | `exact` 占比 ≥ 70% | exact 条目 / 全部 bookRefs |
| 题点比 | 每知识点 3–8 题 | 题库总量 / 知识点数 |
| 解析完整率 | 100% | 有 explain 的题 / 总题 |
| 内容陈旧率 | 每学期复核一次 | 最后复核时间 |

## 8. 内容更新与存档一致性

- 内容更新只影响「新题新点」，不改历史会话记录。
- 删除题目前，先查存档中是否有引用：有引用的题目改为「标记下架」（`retired: true`），保留题干用于复盘展示，不再进入组卷。
- 知识点被合并时，旧 id 在 `aliases` 中登记，旧链接重定向到新 id，避免历史内链失效。
- `dataVersion` 随内容发布递增，写入存档；用于判断「本次内容更新是否影响未完成草稿」（若有题下架，草稿校验时剔除并提示）。

## 9. 书库 UI 与内容的对应

| UI 元素 | 数据来源 | 缺失时 |
| --- | --- | --- |
| 书目卡标题 / 版次 | `Book.title/edition` | 不渲染该卡 |
| 章节树 | `Book.chapters` | 显示「暂无章节索引」，仍可挂载 PDF |
| 章节题量 | `questionsByChapter` 聚合 | 显示 0 并提示「本章暂无题」 |
| 跳页按钮 | `bookRefs.page` + 偏移 | 未挂载时按钮变为「挂载 PDF」 |
| 学习进度 | 子树掌握度均值 | 无练习记录时显示「未开始」 |
