# 01 · 需求规格说明书（SRS）

- 版本：v1.0（首个可交付版本）
- 适用范围：知栈考研知识库平台 Web 端（公共课 + 408，静态站点，单人本地档案）
- 关联文档：架构见 02，数据见 03，交互见 04，内容见 05/06，算法见 07/08，验收见 11

---

## 1. 文档目的与读者

本文定义系统必须提供的能力、可度量的验收标准与不可逾越的边界，作为开发、测试、验收的唯一需求基线。读者为开发者（本人）、测试者与未来维护者。需求编号一经发布不复用；删除的需求标记为 `已废止` 并保留编号。

## 2. 系统概述

### 2.1 系统边界

```
[浏览器]
  ├─ 静态资源（HTML/JS/CSS，GitHub Pages 提供）
  ├─ 内置数据包（知识点 / 题库 / 书目 / 卡池，构建期打包）
  ├─ 本地存档（localStorage：进度、错题、卡册、任务）
  └─ 本地文件（IndexedDB：用户自备 PDF 句柄与二进制）
```

系统不与任何服务器通信；除首次加载静态资源外无网络依赖。

### 2.2 角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 学习者（唯一角色） | 使用本站复习的个人用户 | 全部功能；数据仅本机可见 |
| 访客 | 未产生学习数据的首次访问者 | 可浏览全部内容；答题前需初始化档案（自动完成，无需注册） |

v1.0 不区分管理员与普通用户。内容维护者通过修改仓库内 JSON 并重新部署来更新内容，不进入运行时。

### 2.3 运行环境

| 项 | 要求 |
| --- | --- |
| 浏览器 | Chromium 内核 ≥ 110 / Safari ≥ 16 / Firefox ≥ 110 |
| 视口 | 360×640 起可用；≥ 1280 宽为最佳体验 |
| 存储 | localStorage 可用且剩余 ≥ 1 MB；IndexedDB 可选（缺失时降级为不挂载 PDF） |
| 网络 | 仅首屏加载需要；之后可离线使用（刷新需缓存命中） |

## 4. 功能需求

优先级：`P0` 必须（缺失则版本不可发布）、`P1` 应当、`P2` 可选。每条含验收标准（AC）。

### 4.1 书库（FR-A）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-A-01 | 展示全科书目卡片，含书名、作者、版次、出版社、科目色、章节数、已挂载状态 | P0 | 七科各至少 1 本；卡片信息与数据源一致；缺字段时显示占位而非空白 |
| FR-A-02 | 书目详情展示两级章节树（章 → 节），节点显示题量与掌握度 | P0 | 展开/收起无卡顿；节点题量与题库实际匹配数一致 |
| FR-A-03 | 章节节点可一键打开关联知识点列表 | P0 | 点击后进入筛选态，列表非空（无关联时显示空态与解释） |
| FR-A-04 | 章节节点可跳转至本地 PDF 指定页 | P0 | 已挂载时新标签打开并定位到页；未挂载时提示挂载入口，不报错 |
| FR-A-05 | 支持挂载本地 PDF（单本），记录文件名、大小与挂载时间 | P0 | 刷新后仍可跳转（句柄持久化成功）或明确提示需重新挂载（降级） |
| FR-A-06 | 支持解除挂载并清除本地文件副本 | P0 | 解除后 IndexedDB 对应记录删除；跳页入口回到未挂载态 |
| FR-A-07 | 书目支持「学习进度」条：已掌握章节 / 总章节 | P1 | 进度按掌握度阈值计算，口径与知识点页一致 |
| FR-A-08 | 展示书籍「如何使用」说明（页码为印刷页，注意 PDF 偏移） | P1 | 说明可见且提供偏移校准入口（见 FR-A-09） |
| FR-A-09 | PDF 页码偏移校准（印刷页 ↔ PDF 页） | P1 | 设置偏移后所有跳页按偏移换算；偏移可重置为 0 |
| FR-A-10 | 书籍数据不足时优雅降级：显示「暂无章节索引」并仍可挂载 PDF | P1 | 不出现空白页或报错 |

### 4.3 练习（FR-C）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-C-01 | 练习入口：模拟组卷、真题原卷、错题重练、薄弱点专项 | P0 | 四个入口可达；每个入口有适用范围说明 |
| FR-C-02 | 组卷参数：科目（多选）、题型、题量（10/20/30/自定义 ≤ 60）、限时（不限/30/45/60/90 分钟） | P0 | 参数变化即时预览可用题量；题量超过可用题量时禁用开始并提示 |
| FR-C-03 | 组卷去重：同一份卷内不出现重复题；优先覆盖多知识点 | P0 | 券内题干 ID 唯一；知识点覆盖数 ≥ min(题量, 可用知识点数) 的 70% |
| FR-C-04 | 答题界面：题干、选项、单选/多选/判断控件、进度、计时、题目导航面板、标记、上一题/下一题 | P0 | 键盘 1–4 / A–D 可选，Enter 下一题；导航面板可跳题并显示作答状态 |
| FR-C-05 | 答题过程自动草稿：刷新或误关后可恢复未交卷会话 | P0 | 恢复后答案、剩余时间、当前位置一致；过期（> 24 h）会话提示后清除 |
| FR-C-06 | 交卷校验：未答题提示确认（显示未答数量），支持「继续作答 / 直接交卷」 | P0 | 两种选择均生效，不丢答案 |
| FR-C-07 | 评分：单选/判断全对得分，多选按「全对才得分」或「漏选半分」策略（可配置，默认漏选半分、错选 0） | P0 | 得分计算与策略一致；总分展示正确率与用时 |
| FR-C-08 | 逐题解析：正确答案、解析、考点标签、知识点链接、难度 | P0 | 解析缺失时显示「暂无解析」而非空块；链接可达 |
| FR-C-09 | 交卷后题目可按「全部 / 答错 / 未答 / 标记」筛选复盘 | P1 | 筛选即时生效，计数与实际一致 |
| FR-C-10 | 真题原卷：按年份整套发卷，保留真实题号、分值与时长；题干不改写 | P0 | 原卷题不进入随机组卷；图形题标注来源 |
| FR-C-11 | 练习记录：保存每次会话的科目、题量、正确率、用时、时间戳 | P0 | 统计页可读到全部记录；记录上限 500 条，超出按时间淘汰 |
| FR-C-12 | 练习中断与退出：二次确认，草稿保留 | P1 | 退出后可恢复；主动放弃则清除草稿并确认 |
| FR-C-13 | 计时到点自动交卷，未答题按错误计 | P0 | 到点 3 秒内自动交卷；提示已自动提交 |
| FR-C-14 | 题干/选项内公式与代码以等宽或上下标正确排版（如 `O(log n)`、`2^32`） | P1 | 不出现原样 `^` 与 `_` 拼接导致的歧义（用行内标记渲染） |
| FR-C-15 | 张冠李戴防护：同一题在模拟卷与错题本中出现时，状态互不干扰 | P1 | 会话作答数据按会话隔离，不写回题库 |
| FR-C-16 | 主观题自评：交卷前展示参考答案与评分要点，支持 0–100% 六档比例 | P0 | 得分 = 满分×比例；60% 及以上计答对；超时按 0 分 |

### 4.4 错题（FR-D）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-D-01 | 答错自动入错题本，记录首次时间、最近时间、错误次数、错误选项、来源会话 | P0 | 同题多次答错合并一条并累加次数 |
| FR-D-02 | 错题排序：默认按「错误次数 × 近因权重」，可切换最近 / 科目 / 掌握度 | P0 | 排序结果稳定；切换有明确选中态 |
| FR-D-03 | 错题重练：单题抽练或批量（最多 20 题） | P0 | 批量按排序取前 N；答完给出即时对错与解析 |
| FR-D-04 | 状态机：`new → reviewing → mastered`，答对 2 次（可跨会话）出本；答错回退到 `new` | P0 | 状态变化即时可见；出本后从列表移除并可「查看已出本」 |

### 4.7 诊断与推荐（FR-G）

## 5. 外部接口需求

| 接口 | 说明 |
| --- | --- |
| 静态资源 | GitHub Pages 提供 `index.html`、带哈希的 JS/CSS；`base=/zhistack/` |
| 本地文件 | `File System Access API`（Chromium）或 `<input type=file>` + `Blob` URL（降级） |
| 浏览器存储 | `localStorage`（存档）、`IndexedDB`（PDF Blob/句柄） |
| 剪贴板 | 导出存档时提供「复制 JSON」便捷项（可选） |
| 无服务端接口 | 明确不调用任何远程 API |

## 6. 数据需求

| 数据类 | 规模（v1.0） | 位置 | 可变性 |
| --- | --- | --- | --- |
| 知识点 | 150–180 条，七科均衡（每科 ≥ 20） | `src/data/knowledge/*.js` | 构建期固定 |

| PDF | 单本 ≤ 300 MB（建议） | `IndexedDB` | 用户可控，可删除 |

## 7. 性能与容量要求（摘要）

- 首屏可交互 ≤ 1.5 s（本地生产构建，中端设备）；路由切换 ≤ 200 ms。
- 检索 140 条知识点（含正文）≤ 30 ms。
- 组卷 160 题池 ≤ 20 ms；交卷评分 + 写档 ≤ 50 ms。
- 单次写存档 ≤ 10 ms（200 KB 量级），答题过程每 3 题或每 10 s 防抖落盘一次。

## 8. 约束、假设与依赖

1. 无后端意味着跨设备同步只能手工导入导出；产品文案不得承诺「自动同步」。
2. GitHub Pages 不支持 SPA 回退，路由必须为 hash 模式。
3. 题库与知识点为静态数据，更新需重新部署；运行时不做内容编辑（避免内容与存档版本错位）。
4. PDF 挂载依赖浏览器能力；Safari 与 Firefox 走 Blob URL 降级（每次会话需重新挂载），文案需明确。
5. 概率型功能必须展示概率公示与保底规则，符合常见的「抽卡公示」惯例。
