# 02 · 系统架构设计

## 1. 架构总览

知栈是**无服务端的单页应用**。所有能力在浏览器内闭环，GitHub Pages 只承担静态分发。这个选择带来三个直接后果，也决定了后面所有设计：

1. 内容不可在运行时编辑，只能随仓库更新 → 数据层必须构建期校验，避免脏数据上线。
2. 状态只在本机 → 存储层必须自带版本、校验、备份与迁移，否则一次浏览器清缓存就等于清零。
3. 无网络依赖 → 检索、组卷、评分、推荐全部本地算法，性能预算以「毫秒级」为硬约束。

```
┌──────────────────────────────────────────────────────────────┐
│                       浏览器（单页应用）                       │
│                                                              │
│  视图层  views/  ── 通用组件 components/  ── 设计令牌 tokens  │
│     │                                                        │
│  状态层  stores/  (Pinia: profile / practice / library /      │
│     │             gacha / tasks / settings)                   │
│     │                                                        │
│  领域层  core/    (search / paper / grade / diagnose / gacha  │
│     │             / tasks / stats ——  纯函数，无副作用)        │
│     │                                                        │
│  数据层  data/ (构建期静态包)   storage/ (localStorage+IDB)    │
│                                                              │
│  平台层  路由(hash) · 主题 · 键盘 · 文件挂载 · 错误边界         │
└──────────────────────────────────────────────────────────────┘
                              │ 静态资源
                    GitHub Pages（Actions 构建产物）
```

分层原则：**视图只读状态、只发意图**；领域层是纯函数，输入数据输出结果，便于用 Node 脚本单测；存储层是唯一可写持久化的地方；数据层只读。

## 2. 模块划分

| 层 | 模块 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 视图 | `views/Home` `Library` `BookDetail` `Knowledge` `KnowledgeDetail` `Practice` `Session` `Mistakes` `Gacha` `Tasks` `Stats` `Settings` | 布局、交互、展示 | 不做计算，不直接读写 localStorage |
| 组件 | `AppShell` `NavRail` `QuestionCard` `OptionList` `TimerRing` `QuestionNav` `ResultPanel` `CardFace` `StampGrid` `TaskRow` `RadarChart` `Heatmap` `SearchBox` `EmptyState` `Modal` `Toast` | 可复用 UI 单元 | 不持有跨页业务状态 |
| 状态 | `useProfileStore` `usePracticeStore` `useLibraryStore` `useGachaStore` `useTaskStore` `useSettingsStore` | 聚合状态、编排动作、落盘 | 不实现算法 |
| 领域 | `search.ts` `paper.ts` `grade.ts` `diagnose.ts` `gacha.ts` `taskEngine.ts` `stats.ts` `mastery.ts` | 纯计算 | 不依赖 DOM |
| 数据 | `subjects.js` `knowledge.js` `questions.js` `books.js` `cards.js` `taskDefs.js` `index.js`（导出与索引构建） | 静态内容 + 预建索引（Map / 倒排） | 不含逻辑 |
| 存储 | `archive.ts` `migrate.ts` `pdfStore.ts` `backup.ts` | 读写、校验、迁移、备份 | 不含业务规则 |

## 4. 路由设计

| 路径 | 视图 | 说明 | 参数 |
| --- | --- | --- | --- |
| `/` | Home | 仪表盘：今日任务、薄弱点、继续学习、数据概览 | — |
| `/library` | Library | 书库列表 | `?subject=` |
| `/library/:bookId` | BookDetail | 章节树、挂载、跳页 | `?chapter=` |
| `/knowledge` | Knowledge | 检索与筛选 | `?q= &subject= &chapter= &mastery=` |
| `/knowledge/:kid` | KnowledgeDetail | 知识点详情 | — |
| `/practice` | Practice | 练习中心（五种入口） | `?tab=` |
| `/practice/session/:sid` | Session | 答题会话（草稿态也可进入） | — |
| `/practice/result/:sid` | Session（结果态） | 交卷结果与复盘 | `?filter=` |
| `/mistakes` | Mistakes | 错题本 | `?sort=` |
| `/gacha` | Gacha | 抽卡与卡册、集章 | `?tab=pull|album|stamps` |
| `/tasks` | Tasks | 任务与成就 | — |
| `/stats` | Stats | 统计 | `?range=7|30|90` |
| `/settings` | Settings | 主题、存档、挂载、关于 | — |

hash 模式（`#/path`）是为了 Pages 不做 404 回退；筛选态写进 hash query，保证「复制链接即复现视图」。

## 5. 状态管理与数据流

### 5.1 Store 划分

| Store | 持有 | 主要动作 | 落盘时机 |
| --- | --- | --- | --- |
| `settings` | 主题、启用科目、书籍页码偏移、引导完成标记 | `setTheme` `toggleSubject` `setOffset` | 即时 |
| `library` | 当前书目、挂载状态、检索词与筛选 | `mountPdf` `unmount` `search` | 挂载状态即时，检索态不落盘 |
| `practice` | 当前会话、草稿、历史记录 | `createPaper` `answer` `submit` `resume` | 每 3 题或 10 s 防抖；交卷立即 |
| `profile` | 累计统计、日度聚合、知识点掌握原料、错题、积分流水、等级 | `recordAnswer` `recordSession` `addPoints` | 随 practice 落盘 |
| `gacha` | 卡册、碎片、保底计数、抽卡历史 | `pull` `exchange` | 即时 |
| `task` | 当日/本周任务进度、成就 | `syncFromEvent` `claim` | 即时 |

### 5.2 事件流（单次答题）

```
QuestionCard 选择答案
   → practiceStore.answer(qid, keys)
       → 更新会话草稿（内存）
       → 每 3 题 / 10 s 防抖 → archive.write()
   → 交卷 practiceStore.submit()
       → core/grade.gradeSession(session, questions)   // 纯函数
       → profileStore.recordSession(result)            // 聚合统计
       → profileStore.recordAnswers(result.items)      // 知识点尝试/错题状态机
       → taskStore.syncFromEvent({type:'answer', ...}) // 任务进度
       → gachaStore.awardPoints(earned)                // 积分流水
       → taskStore.checkAchievements()
       → archive.write(immediate)
```

关键约束：**领域计算结果先算完，再一次性写盘**，避免中途崩溃导致统计与错题不一致。所有写盘通过 `archive.commit(patch)` 串行化。

### 5.3 派生与缓存

- 知识点索引（倒排、题干索引）在模块加载时构建一次，随数据规模线性增长（140 条量级可忽略）。
- 掌握度与薄弱排行是派生数据，不落盘；每次进入首页/诊断页按当前原料重算（毫秒级）。
- 卡池概率、任务定义、书目结构只读，不进入存档，减小存档体积。

## 6. 关键算法位置

| 能力 | 模块 | 复杂度 | 说明 |
| --- | --- | --- | --- |
| 检索 | `core/search.js` | O(n·m) | 分词 + 字段权重 + 子串高亮；n ≤ 140 |
| 组卷 | `core/paper.js` | O(n) | 分层抽样：按知识点去重 + 难度配额 |
| 评分 | `core/grade.js` | O(k) | 多选策略可配置，主观题走关键词自评 |
| 掌握度 | `core/mastery.js` | O(1)/知识点 | 正确率 × 置信度 × 近因 |
| 诊断 | `core/diagnose.js` | O(n log n) | 排序取 Top N，附理由 |
| 抽卡 | `core/gacha.js` | O(1) | 概率表 + 双保底计数 |
| 任务 | `core/tasks.js` | O(t) | 事件 → 指标累加 → 达标判定 |

## 7. 性能设计

1. **首屏**：路由级懒加载（`() => import()`），首页只加载 dashboard 所需模块；数据包按科目拆分可选（v1.0 数据量小，先整包）。
2. **检索**：不做逐字正则全文扫描，改为「预建 token 集合 + 子串匹配」，并对 `<mark>` 高亮只在渲染前 20 条结果中执行。
3. **长列表**：知识点与题目列表均 ≤ 200 项，直接渲染；错题 > 100 条时按 20 条分页。
4. **写盘节流**：答题草稿防抖 10 s / 3 题；统计聚合在交卷时一次写入。
5. **动画**：仅使用 `transform` / `opacity`，避免布局抖动；抽卡 SSR 光效用 CSS 渐变与遮罩，不引入 canvas 库。
6. **图表**：手写 SVG path，雷达与热力为纯 DOM/SVG，无第三方库。

## 8. 可靠性设计

| 风险 | 措施 |
| --- | --- |
| 存档损坏 | 读取时 try/catch + 结构校验；失败依次尝试 3 份备份；仍失败则新建空档并把损坏原文导出 |
| 写入失败（配额满） | 捕获 `QuotaExceededError`，提示清理（导出后清空历史会话/抽卡记录），并降级为只读模式 |
| 数据与代码版本错位 | 存档带 `schemaVersion` 与 `dataVersion`；不匹配时执行迁移或提示 |
| 题库下线导致幽灵题 | 渲染前用 `questionIndex` 校验存在性，缺失显示「题目已下架」 |
| 汇总统计漂移 | 统计以「会话记录 + 答题明细」为唯一事实源，累计值可由明细重算（提供「重建统计」入口） |
| 概率争议 | 概率公示 + 保底计数可见 + 抽卡历史可查 |

## 9. 安全与隐私

- 无远程请求，无第三方脚本，无埋点；`index.html` 不引入外链字体或 CDN。
- 引用的外部链接（书目出版社页面）使用 `rel="noopener noreferrer"`。
- 用户导入的 JSON 只按固定 schema 取值，不 `eval`、不渲染 HTML；所有文本以 `v-text`/插值渲染，避免 XSS。
- 本地 PDF 文件只在浏览器内经 Blob/句柄访问，不上传、不复制进仓库。
- 导出文件不含任何身份信息（仅学习数据）。

## 10. 部署形态

```
git push main
   → Actions: setup-node@v4 (npm ci) → validate-data → vite build
   → upload-pages-artifact(dist)
   → deploy-pages
   → https://by-be-young.github.io/kaoyan-408/
```

构建产物约 300–600 KB（gzip 后 ~150 KB），无外部 CDN 依赖，Pages 边缘缓存即可。回滚方式见 12-部署与运维手册。

## 11. 技术选型理由（摘要）

| 选型 | 理由 | 放弃的方案 |
| --- | --- | --- |
| Vue 3 + `<script setup>` | 组合式 API 适合「纯函数领域层 + 薄视图」，模板编译体积小 | React（需额外状态与样式方案，体积更大） |
| Vite | 秒级冷启动与构建，天然适配 Pages 静态产物 | Webpack（配置重） |
| Pinia | 轻量、可组合、无魔法；多 store 按域拆分 | Vuex（模板化） |
| hash 路由 | Pages 无 404 回退，hash 免配置 | history 模式（需 404.html hack） |
| localStorage + IndexedDB | 存档小、同步读写；大文件单独放 IDB | 全 IDB（异步成本高）、全 localStorage（容量不够） |
| 原生 CSS 令牌 | 视觉可控、零依赖、易做主题 | Tailwind（产物与定制成本）、UI 框架（风格受限） |
| 手写 SVG 图表 | 极轻、可完全控制视觉 | ECharts（> 300 KB） |
