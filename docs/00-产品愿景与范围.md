# 00 · 产品愿景与范围

## 1. 一句话定义

知栈是一个**单机可用的全科考研工作台**：以知识点为索引，把教材书页、练习题、错题与复习计划咬合在一起，并用轻量的收集与抽卡机制维持长期复习动机。覆盖数学（一）、英语（一）、政治与 408 四门专业课。

## 2. 背景与问题

考研备考的典型困境，不在「缺资料」，而在「资料之间是断的」：

1. **书与点分离**。教材按章节写，考点按知识域考。复习时在「第 3 章 3.4 节」和「虚拟内存」之间来回翻，翻书成本高于理解成本。
2. **点与题分离**。看完一个知识点，找不到对应题；做完一道题，不知道它考的是哪一条。错题本只剩题干，没有回到知识点的路径。
3. **错题不回流**。错题抄下来就结束，缺少「隔多久再练、练几次算掌握」的机制，复习变成重复劳动。
4. **薄弱点靠感觉**。「计组好像不太行」是一种情绪，不是可执行的结论。缺少按知识点粒度的正确率统计，练习量被平均分摊。
5. **长期动机衰减**。刷题到第三个月，正反馈消失，进度不可见，容易断更。

现有工具各管一段：笔记软件管知识、题库 App 管做题、Anki 管间隔重复、Excel 管进度。知栈要做的是**把这几段合成一条流水线**，且不依赖服务器、不依赖账号、不产生云端隐私风险。

## 3. 目标用户与画像

| 画像 | 特征 | 核心诉求 | 对产品的约束 |
| --- | --- | --- | --- |
| 主用户：应届考生（软工 / 计科 / 跨考） | 大三下至大四上，公共课与 408 并行，日均可支配 2–4 小时 | 快速定位考点、按薄弱点刷题、进度可见 | 移动端也要能用；离线可用；启动快 |
| 次用户：二战 / 跨考生 | 基础薄弱，需要从章节结构入手 | 章节级导航、概念补强、低门槛练习 | 需要更细的知识点摘要与难度分层 |
| 边缘用户：复试复习者 / 课程学生 | 只用某一科，或只查概念 | 检索、单科练习 | 允许只启用部分科目，不强迫全流程 |

主用户的技术背景使其能接受「本地挂载 PDF」这类操作，但不能接受复杂配置。产品默认零配置可用：打开网页即有完整知识点与题库。

## 4. 使用场景（Story）

- **S1 查考点**：做真题遇到「TLB 与 Cache 的关系」，搜索 `TLB`，命中知识点卡片，卡片底部列出「关联书页：计组 · 第 4 章 · p.132」，点击即打开本地 PDF 对应页，右侧是 3 道关联题。
- **S2 组卷自测**：考前两周，选择「操作系统 + 计组」，20 题 / 45 分钟，交卷后得到分数、逐题解析、知识点归因。
- **S3 错题回流**：交卷后错题自动入本。三天后打开错题本，系统按「错误次数 × 近因」排序，重练答对一次进入观察区，连续答对两次出本。
- **S4 薄弱点攻坚**：首页给出「本周最该补的 3 个知识点」，附推荐理由（正确率 43%、近 7 天错 4 次、覆盖 12 道候选题）。
- **S5 日常激励**：完成每日任务得积分，攒够 60 分抽一次知识卡，抽到重复卡转化为碎片，集满一章的卡点亮对应「章印」。
- **S6 换设备**：导出 JSON 存档，在新设备导入，进度、错题、卡册、任务状态全部接续。

## 5. 产品目标与成功指标

| 目标 | 指标 | 目标值（首个版本上线后 30 天，个人使用口径） |
| --- | --- | --- |
| 降低「找内容」成本 | 从搜索到打开书页的操作步数 | ≤ 3 步 |
| 提升练习针对性 | 推荐练习中被采纳的比例 | ≥ 50% |
| 错题真正闭环 | 错题出本率（连续答对 2 次） | ≥ 40% |
| 维持长期动机 | 周活跃 ≥ 4 天；连续打卡 ≥ 14 天 | 达成 |
| 可用性 | 冷启动首屏可交互 | ≤ 1.5 s（本地构建产物，中端笔电） |
| 稳定性 | 存档损坏导致进度丢失 | 0 例（含备份与校验） |

> 指标用于自我校准，不引入埋点上报。所有统计在本地计算，用户可自行导出。

## 6. 产品原则

1. **本地优先**。默认无账号、无网络请求、无上报。数据归用户，随时可导出。
2. **一条链路到底**。任何内容页都必须能通向「相关题」，任何题都必须能通向「相关知识点」。
3. **结论可解释**。「薄弱」必须给出公式与依据（正确率、样本量、近因），不用黑箱评分。
4. **奖励不打断学习**。积分与抽卡是收尾的甜点，不在答题过程中弹窗。
5. **信息密度优先，装饰克制**。一屏内先给结构与数字，再给氛围；动效只用于状态变化提示。

## 7. 范围

### 7.1 本期范围（v1.0）

- 七科知识点库（原创讲义摘要）：数学、英语、政治与 408 四科，全文检索、章节与书页映射
- 本地 PDF 挂载与按章节 / 页跳转
- 题库：单选、多选、判断；模拟组卷、历年原卷整套训练、自由练习
- 错题本、错题重练、掌握度状态机
- 积分、等级、打卡、连击、抽卡、卡册、集章、每日 / 每周任务、成就
- 薄弱知识点诊断与推荐练习
- 学习统计（日历热力、科目雷达、趋势、错题分布）
- 存档导入导出、数据重置、主题切换（浅 / 深）

### 7.2 明确不做（Out of Scope）

- 教材正文托管、扫描件分发、任何形式的全文转载
- 云端账号、跨设备自动同步、排行榜、社交互动
- 主观题自动判分（v1.0 仅支持关键词自评，见 06 文档）
- 视频课程、直播、付费内容
- 服务端推荐模型与 AB 实验

### 7.3 后续候选（详见 13-路线图）

间隔重复调度（SM-2 变体）、错题按「错误类型」聚类、题目收藏夹、笔记与批注、PWA 离线安装、多用户本地档案、真题整卷还原。

## 8. 约束与假设

| 类别 | 内容 |
| --- | --- |
| 平台 | 现代浏览器（Chrome / Edge / Safari 最新两个大版本）；桌面为主，移动端可用 |
| 部署 | GitHub Pages 静态托管，子路径 `/zhistack/`，无服务端 |
| 存储 | `localStorage` 约 5 MB 上限，存档控制在 200 KB 内；大文件（PDF）走 IndexedDB |
| 内容 | 内置题库规模 ≥ 120 题、知识点 ≥ 100 条；不足部分由用户自行扩展（JSON 导入为后续项） |
| 合规 | 不复制受版权保护的教材正文与真题原文；书目信息为公开出版信息 |
| 时间 | 单次答题会话 ≤ 90 分钟；页面常驻不超过 2 小时（避免状态过旧） |

## 9. 名词约定

产品的「知识点」指可检索、可挂题、可评价的最小复习单元（例：`页式存储的地址转换`），不等于教材小节；「章节」指书目结构中的层级节点；「考点编号」用于跨书对齐（例：`OS-3.2-04`）。完整定义见 [16-术语表](16-术语表.md)。
