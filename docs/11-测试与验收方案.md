# 11 · 测试与验收方案

## 1. 测试策略

静态单机应用没有后端，风险集中在三处：**算法正确性**、**存档一致性**、**交互边界**。因此测试分四层：

| 层 | 范围 | 手段 | 执行时机 |
| --- | --- | --- | --- |
| L1 数据校验 | 静态数据完整性 | `scripts/validate-data.mjs` | 每次构建前（`prebuild`） |
| L2 算法单测 | 检索、组卷、判分、掌握度、诊断、抽卡、任务 | Node 脚本断言（纯函数） | 提交前手动 / CI 可选 |
| L3 流程联调 | 答题 → 交卷 → 错题 → 积分 → 任务 → 抽卡 | 浏览器手动脚本化清单 | 每次发布前 |
| L4 兼容与体验 | 多浏览器、多尺寸、键盘、动画偏好 | 手动 + 检查表 | 每个里程碑 |

## 4. 验收清单（发布门禁）

- [ ] `npm run build` 通过，`validate-data` 无硬错误。
- [ ] 七科知识点 ≥ 20、题目 ≥ 20、卡 ≥ 12。
- [ ] 全部 P0 需求用例通过（TC 表逐项打勾）。
- [ ] 首页 / 书库 / 知识点 / 练习 / 错题 / 卡册 / 任务 / 统计 / 设置 九页可达且无空白。
- [ ] 完整走通一次「组卷 → 交卷 → 错题 → 抽卡 → 任务结算」。
- [ ] 导出 → 清空 → 导入，数据一致。
- [ ] 360 px 与 1440 px 截图检查，无溢出。
- [ ] 线上 URL 返回 200，深层路由可打开。
- [ ] README 站点链接可访问，文档索引链接无 404。

## 5. 回归策略

- 每次内容更新：跑 L1 + 抽查 5 条知识点与 5 道题的渲染。
- 每次算法调整：跑 L2，更新基线数值并在文档中记录变更。
- 每次视觉调整：至少检查深/浅 + 移动/桌面四张截图。
- 发布前手工备份一次线上存档（导出 JSON），用于回滚验证。

## 6. 缺陷分级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| S1 阻断 | 无法答题 / 数据丢失 / 白屏 | 立即修复，不发版 |
| S2 严重 | 计分错误 / 错题状态错 / 存档失败 | 当版修复 |
| S3 一般 | 布局溢出 / 文案错误 / 空态缺失 | 当版或下版 |
| S4 轻微 | 动效不顺 / 间距微差 | 排期 |
