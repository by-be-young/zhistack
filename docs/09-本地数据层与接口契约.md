# 09 · 本地数据层与接口契约

## 1. 目标

数据层是**唯一可写持久化**的入口。所有页面与 store 通过它读写，禁止直接操作 `localStorage` 或 `IndexedDB`。它要保证：版本可控、写入串行、失败可恢复、导出可迁移。

## 2. 存储介质

| 介质 | 键 / 库 | 内容 | 容量策略 |
| --- | --- | --- | --- |
| localStorage | `zhizhan.archive.v2` | 学习存档（JSON） | 目标 ≤ 200 KB；≥ 80% 配额警告 |
| localStorage | `zhizhan.backup.0/1/2` | 最近 3 份备份（滚动） | 各 ≤ 200 KB |
| localStorage | `zhizhan.flags` | 轻量标记（引导完成、主题缓存） | < 2 KB |
| IndexedDB | `zhizhan-pdf` / `files` | PDF Blob 与文件名、大小、挂载时间 | 单本 ≤ 300 MB 建议 |
| sessionStorage | `zhizhan.session.tmp` | 会话心跳（防多标签页并发写） | < 1 KB |

> 主题与引导标记单独放 `flags`，避免主存档损坏时连界面偏好都丢失。

## 3. 对外 API

### 3.1 存档读写 `storage/archive.js`

```ts
init(): Promise<Archive>            // 加载或初始化；含迁移、备份回退
read(): Archive                     // 同步读内存副本（只读）
commit(patch: DeepPartial<Archive>, opts?: {immediate?: boolean}): void
                                    // 合并写入，串行排队，防抖 300ms（immediate 跳过防抖）
flush(): Promise<void>              // 强制落盘
exportJSON(): string                // 序列化（含 schemaVersion/checksum/exportedAt）
importJSON(text: string): ImportPreview | throws StorageError
reset(opts?: { keepSettings?: boolean }): void
usage(): { bytes: number; quota: number; ratio: number }
rebuild(): void                     // 由明细重算聚合（统计漂移修复）
```

`commit` 语义：
- 浅合并 `settings/profile/tasks/cards`，数组类（`sessions`/`pointLog`）按 id 去重追加。
- 写入前执行 `validateArchive()` 轻校验（字段类型、枚举、长度上限）。
- 队列串行：同一时刻只有一个写操作；写入失败不丢内存状态，下次写入重试。

### 3.2 PDF `storage/pdfStore.js`

```ts
putFile(bookId: string, file: File): Promise<{ name, size, at }>
getBlob(bookId: string): Promise<Blob | null>
getMeta(bookId: string): Promise<{ name, size, at } | null>
remove(bookId: string): Promise<void>
has(bookId: string): Promise<boolean>
```

- 优先 `showOpenFilePicker` 存句柄（需用户手势，刷新后可用）；不支持时存 Blob（会话内可用，刷新后需重挂）。
- 记录 `mode: 'handle' | 'blob'`，UI 据此提示「刷新后需重新挂载」。

### 3.3 备份 `storage/backup.js`

```ts
rotate(snapshot: Archive): void      // 写 backup.0，旧份后移
list(): BackupMeta[]                 // 时间、版本、题量
restore(index: number): Archive
```

规则：每日首次 `commit` 前调用一次 `rotate`；同一日多次写入不重复备份。

## 4. 存档校验与错误码

| 错误码 | 触发 | 用户可见文案 | 处理 |
| --- | --- | --- | --- |
| `E_PARSE` | JSON 解析失败 | 存档无法读取，已尝试恢复备份 | 依次尝试备份；失败则新建空档 + 提供损坏原文下载 |
| `E_SCHEMA` | 字段缺失/类型错 | 存档结构不完整 | 走 `repair()` 补默认值并记录 |
| `E_VERSION_NEW` | `schemaVersion` 高于当前 | 存档来自更新版本，请使用对应版本或导出备份 | 只读模式，不写入 |
| `E_MIGRATE` | 迁移抛错 | 版本升级失败，已保留原档 | 回滚到备份，只读 |
| `E_QUOTA` | `QuotaExceededError` | 本地存储空间不足 | 提示清理历史，降级只读 |
| `E_IMPORT_INVALID` | 导入结构非法 | 文件不是有效的知栈存档 | 拒绝，不覆盖现有 |
| `E_IMPORT_CHECKSUM` | 校验和不符 | 文件可能被修改，仍可强制导入 | 二次确认后导入 |

## 5. 导出格式

```jsonc
{
  "app": "zhizhan-408",
  "schemaVersion": 2,
  "dataVersion": "1.0.0",
  "exportedAt": "2026-11-26T21:40:00+08:00",
  "checksum": "sha256:…",       // 对 payload 的稳定序列化结果
  "summary": { "questions": 412, "sessions": 21, "cards": 27, "mistakes": 34, "points": 1280 },
  "payload": { …Archive… }
}
```

- 校验和用简单滚动哈希（无需加密库），仅用于检测手改与截断。
- 文件名：`zhizhan-408-存档-YYYYMMDD-HHmm.json`。
- 导出不含 PDF、不含任何设备标识。

## 6. 事件契约

领域层与 store 之间用轻量事件对象，禁止在组件里散落业务判断：

```ts
type AppEvent =
  | { type: 'answer'; qid: string; knowledgeId: string; correct: boolean; firstToday: boolean }
  | { type: 'session-end'; sessionId: string; count: number; correct: number; mode: string }
  | { type: 'mistake-review'; qid: string; result: 'right' | 'wrong'; cleared: boolean }
  | { type: 'knowledge-view'; kid: string; first: boolean }
  | { type: 'book-open'; bookId: string; page: number }
  | { type: 'gacha'; rarity: Rarity; dup: boolean }
  | { type: 'day-rollover'; from: string; to: string }
```

消费方：
- `profile`：更新知识点原料、错题状态机、日度聚合。
- `task`：按 `metric` 累加进度。
- `gacha/points`：产出积分（经日上限过滤）。

`day-rollover` 由 `core/time.js` 在每次交互入口检查（`ensureDay()`），跨日时重置任务、结算打卡，不在定时器里轮询（页面休眠时定时器不可靠）。

## 7. 并发与多标签页

- 同一浏览器多标签页同时作答会导致后写覆盖。措施：
  1. 会话开始时写 `sessionStorage` 心跳（`tabId + at`）。
  2. 检测到其他标签页心跳 < 60 s 时，提示「另一标签页正在学习，当前为只读」并禁止写。
  3. 交卷时重新读一次存档，合并后再写（乐观并发：以 `updatedAt` 比对，冲突则合并数组、以当前会话为准）。
- v1.0 不引入 `BroadcastChannel` 同步，避免复杂度；只做冲突提示。

## 8. 性能与容量

| 操作 | 预算 | 实现 |
| --- | --- | --- |
| 读档 + 迁移 | ≤ 15 ms | 单次 `JSON.parse`，避免深拷贝大数组 |
| 写档（200 KB） | ≤ 10 ms | `JSON.stringify` + 单 key 写入 |
| 交卷（评分 + 聚合 + 写） | ≤ 50 ms | 评分纯函数，聚合增量更新 |
| 导出 | ≤ 80 ms | 直接序列化内存副本 |
| 导入校验 | ≤ 40 ms | 结构校验 + 摘要计算 |

容量治理：
- `sessions` 500 条、`pointLog` 300 条、`cards.history` 50 条为硬上限，插入时裁剪。
- 超限时优先淘汰最旧会话，保留 `daily` 聚合（保证热力图与趋势不丢）。
- 配额 ≥ 80% 时在设置页显示警告与「压缩存档」按钮（压缩 = 淘汰旧会话 + 清空抽卡历史）。

## 9. 轻量 `repair()`

当结构缺失但可解析时，按默认值补齐并记录 `repairLog`：

```
settings 缺失 → 默认深色、四科全开、偏移 0
profile 缺失 → points 0、streak 0、totals 0
knowledge 缺失 → {}
mistakes 缺失 → {}
cards 缺失 → { owned:{}, shards:0, pitySsr:0, pityR:0, history:[] }
tasks 缺失 → 按当前日期重建
sessions/daily 缺失 → []
draft 缺失 → null
```

`repair` 只在 `E_SCHEMA` 且可解析时执行，不覆盖已有合法字段。

## 10. 接口契约的稳定性

- 对视图暴露的 API 只增不改；破坏性变更同时提升 `schemaVersion` 并写迁移。
- 领域函数签名固定为 `(input, options?) => output`，不读全局、不写存储，便于 Node 脚本测试。
- 所有时间以 ISO 字符串存储，计算时转本地时间；禁止存「相对时间」。
- 所有 ID 为字符串；数字字段统一用 number，不用字符串数字混用。
